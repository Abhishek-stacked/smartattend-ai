# SmartAttend AI — API Contract

Base path `/api`. Interactive, always-current documentation is generated by FastAPI at
`/api/docs` (Swagger UI) and `/api/openapi.json`. This file is the design-level contract.

## 1. Conventions

| Topic | Rule |
|---|---|
| Format | JSON (`application/json`), except image uploads (`multipart/form-data`) and exports |
| Auth | `sa_session` cookie (HttpOnly, SameSite=Lax, Secure in production) |
| CSRF | State-changing methods (POST/PUT/PATCH/DELETE) require header `X-CSRF-Token` equal to the `sa_csrf` cookie. Login and reset-password are exempt. |
| Pagination | `?page=1&page_size=20` (max 100) → `{items, total, page, page_size}` |
| Errors | `{"error": {"code": "string", "message": "human readable", "details": any}}` |
| Times | ISO-8601 with timezone (UTC) |
| Trust | Identity, role, attendance status and eligibility are always derived server-side |

Status codes: `200` OK, `201` created, `204` no content, `400` business rule violation,
`401` unauthenticated, `403` forbidden (role/ownership), `404` not found (also used when an
object exists but the caller may not know it exists), `409` conflict (duplicates),
`413` upload too large, `415` unsupported media, `422` validation, `429` rate limited,
`503` AI model unavailable.

Roles: **A** = admin, **F** = faculty (own courses only), **S** = student (own data only).

### Courses & enrolments
| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/courses` | A (all), F (own) | filters `q`, `department`, `status` |
| POST | `/courses` | A | `{code, name, department, term, faculty_id}` |
| GET / PATCH | `/courses/{id}` | A, F (own, read) | |
| GET | `/courses/{id}/enrollments` | A, F (own) | roster with biometric-enrolled flag |

| DELETE | `/courses/{id}/enrollments/{student_id}` | A | marks enrolment `dropped`; removes the student from the course's scheduled sessions |

### Recognition & liveness (station = authenticated faculty/admin browser)
| Method | Path | Roles | Description |
|---|---|---|---|
| POST | `/recognition/detect` | A, F, S (self-enrolment) | multipart `frame` → `{faces:[{box, score, quality:{ok, issues[], blur, brightness, face_px}}], processing_ms}`; nothing stored |
| POST | `/recognition/recognize` | A, F (own active session) | multipart `frame`, `session_id` → `{results:[FaceResult], processing_ms}` |
| GET | `/recognition/events` | A, F (own courses) | paged; filters `status` (`not_required\|pending\|resolved\|dismissed`), `session_id`, `outcome`, `liveness_status` |
| POST | `/recognition/events/{id}/resolve` | A, F (own courses) | `{action: mark_present\|mark_late\|dismiss, note}` — note 5–500 chars; 409 `already_reviewed`; marking requires a stored candidate and an active/closed session |
| POST | `/liveness/verify` | A, F | multipart `frame` → per-face verdicts; see below. Runs the real model only — a missing model returns `not_enabled`, never a pass |

`FaceResult`:
```json
{
  "box": [x, y, w, h],
  "outcome": "recognized | unknown | low_confidence | poor_quality | multiple_faces | liveness_failed | duplicate | not_eligible | error",
  "student": {"id": 12, "full_name": "…", "registration_number": "…"} ,
  "similarity": 0.61,
  "liveness": {"status": "passed", "score": 0.93},
  "attendance": {"committed": true, "record_id": 88, "status": "present"},
  "event_id": 501,
  "message": "Attendance recorded",
  "cooldown": false
}
```
`student` is present only for `recognized` / `duplicate`. Embeddings are never returned.

`POST /liveness/verify` response:
```json
{
  "faces": [{"box": [x, y, w, h], "status": "passed | failed | inconclusive | not_enabled", "score": 0.93, "message": "…"}],
  "available": true,
  "threshold": 0.6,
  "model": "MiniFASNetV2",
  "model_version": "2.7_80x80",
  "processing_ms": 41,
  "message": "…"
}
```
This endpoint is for on-screen feedback only; it never writes attendance. Liveness policy per session is `off` (no check), `flag` (mark confident identities and queue failed/inconclusive checks for review), or `enforce` (mark only on a passing check; unavailable model → no mark, `error`/`liveness_unavailable`).

### Student self-service
| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/me/summary` | S | own attendance counts plus `registration_number`; filters `date_from`, `date_to`, `course_id` |
| GET | `/me/attendance` | S | paged own records; filters `course_id`, `status`, `date_from`, `date_to` |

`/me/summary` reports `sessions` as the sessions the student participated in and
`unmarked = participants − records`; it never includes another student's counts.

### Student self-marking
A session can let students mark themselves present without a camera, so that a student who
arrives while the teacher is busy is not marked absent by default. It is opt-in per session
and always bounded:

- The window opens at `scheduled_start` and closes at `attendance_closes_at`, which is
  `scheduled_start + window_min` (default 30 minutes) — the window is measured from the start
  of the session, not from its end. Arriving after `late_after`
  (`scheduled_start + late_after_min`, default 10 minutes) is recorded as `late`, not `present`.
- The record is written with `source = self_reported`, so it stays distinguishable from a
  biometric match and from a manual override.
- An existing record is never overwritten — a second self-mark returns the first record.
- Admin/faculty can lock an individual student out of self-marking at any time
  (`self_marking_locked_at` + reason) for misuse, without affecting the rest of the cohort.

`GET /sessions/mine` returns `self_marking_open`, `self_marking_message` and
`self_marking_closes_at` per session so the student UI can show exactly why the button is
missing.

### Reports & dashboards
All figures are aggregated from attendance records on request, within the caller's scope
(A = all, F = own courses). Invalid filters return `422` with `invalid_date_range`,
`invalid_report_type`, `invalid_status` or `invalid_granularity`.

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/reports/summary` | A, F | dashboard cards; filters `date_from`, `date_to`, `course_id` |
| GET | `/reports/trends` | A, F | `granularity=day\|week\|month` (default `day`) → series, status distribution, course comparison |
| GET | `/reports/activity` | A, F | latest recognition events, five latest sessions with counts, pending queues |
| GET | `/reports/attendance` | A, F | `type=daily\|weekly\|monthly\|course\|student\|faculty\|late\|absence\|exceptions\|corrections`, paged (`page`, `page_size` ≤ 100); `status` applies to `corrections` only |
| GET | `/reports/export` | A, F | same filters + `fmt=csv\|pdf`; the response is a file attachment and includes `Content-Disposition` |

`/reports/attendance` returns server-defined `columns` (`key`, `label`, `align`) and `rows`, so the
client renders the same table the CSV/PDF exporter builds. Grouped reports include a `summary` with
per-status totals and `rate`; `rate` is `(present + late) / marked`.

Exports reuse the report filters and scope, cap at 10,000 rows (`422 export_too_large` beyond that),
and prefix CSV cells that start with `=`, `+`, `-`, `@`, tab or carriage return with an apostrophe so
spreadsheets do not evaluate them. PDFs are generated with reportlab as a landscape A4 table.

## 3. Rate limits (per client IP, in-process sliding window)

| Route group | Limit |
|---|---|
| `/auth/login` | 10 / minute per IP + account lockout 15 min after 5 consecutive failures |
| `/auth/reset-password` | 10 / 15 minutes |
| `/recognition/*`, `/liveness/*` | 240 / minute per user |
| everything else | 600 / minute |

The in-process limiter is correct for the single-process deployment used here; a multi-worker
deployment should move it to a shared store (e.g. Redis). **[Planned]**
